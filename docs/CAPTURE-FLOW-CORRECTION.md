# 浏览器获取流程纠正

## 已确认的事实

对照 LitScout Fulltext 0.2.4 与 Download 版，`navigation-pdf-capture.js` 和 `saved-download-bridge.js` 的捕获实现没有实质差异。旧版从文章入口进入；下载版把 `pdfUrl` 提到了浏览器入口首位，改变了公开尝试失败后的路径。

论文 DOI `10.1155/2021/6658575` 的旧任务事件是 `manual_capture_active → pdf_captured → completed`，从监听开始到捕获约 7 秒，身份核验通过。新任务多次出现 `browser_save_detected`，却没有 `pdf_captured`。这证明旧版直接读到了 PDF，而新版在这些尝试中只关联到了下载动作。

入口变化已确认，但仅凭这些事件无法断言每一次读取失败都由同一个原因造成。浏览器 PDF 阅读器、Blob 下载和已发生的响应也可能影响捕获；本次实际出版社复测通过前，不宣称此论文已经恢复。

## 固定流程

1. 首次处理可尝试清单中的公开 PDF：无 Cookie、有超时、有大小限制。成功后仍需核验文献身份。
2. 公开尝试失败后，浏览器优先打开 DOI 文章页；无 DOI 时使用文章页、arXiv 页面或来源页。只有 PDF 链接的清单才直接打开 PDF。
3. 从文章页识别 PDF 入口，先启动响应监听，再打开 PDF。用户完成验证后的“继续”和“监听手动下载”沿用当前标签页。
4. “重新获取 PDF”清除当前文件指针和旧标签页关联，从 DOI 或文章页重新开始，不重复公开预尝试。历史文件和审计事件保留。
5. 捕获完整字节后上传本机，核验通过才对 Agent 开放读取和导出。下载事件本身没有 PDF 字节，不能作为已下载证据。
6. 保存后回传仅是备用路径，仍遵守允许目录边界；不能用要求用户保存替代直接响应捕获。

首次仅有 PDF 链接时，先创建空白标签页、挂载监听，再导航，避免附件响应早于监听。已有文章页的手动捕获模块保持原实现，没有增加反复请求出版社或绕过验证的行为。

## 验证边界

单元测试覆盖入口优先级和重试时关闭公开预尝试。隔离 Chromium 覆盖公开失败回文章页、重新获取不重放公开请求、附件响应在用户保存前捕获，以及原有队列、核验、暂停和导出流程。隔离测试使用合成文件，与实际出版社复测分别报告。
