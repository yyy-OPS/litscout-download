# 0.1.0 测试与验收

日期：2026-10-12。平台：Windows，Python 3.11，真实 Chromium MV3 扩展，临时浏览器 Profile。未修改日常 Edge、旧 Skill、旧服务、原配对或原 PDF。

## 覆盖与结果

| 测试 | 结果 | 覆盖 |
| --- | --- | --- |
| Python 自动回归 | 59 项通过 | 清单协议、幂等、权限、跨浏览器隔离、持久化、队列、核验、导出 |
| 插件 Node 回归 | 50 项通过 | 捕获、分段 PDF、下载关联、缓存预算、通知、失效 worker 错误处理 |
| 真实浏览器隔离冒烟 | 43 个检查点通过 | 插件真实加载配对、侧栏、人工交互、实际下载及 Skill 导出 |
| 批量测试 | 20/20 下载、核验、导出 | 20 个不同题名、DOI、PDF 哈希；每篇导出回执验证 |

无云端验收：从测试子进程清除 CDK 环境变量，Chromium DNS 仅放行本地模拟出版社与回环地址，扩展对 LitScout 云端发起探测并确认不可访问。再通过实际 Skill 命令提交论文 JSON、查询清单、重复提交、读取文本、导出 20 篇。服务端另有禁止 socket 连接的测试，确认无出站请求依赖。

论文均是本地生成的测试 PDF，出版社页面也是本机 TLS fixture。这证明下载工作流可以独立运行，不能推导为 20 篇真实出版社论文成功率，也不保证适配全部出版商。真实校园网访问仍需另安排用户参与的隔离 Profile 测试。

## 用户指定的异常场景

| 场景 | 验证方式 |
| --- | --- |
| 批量队列 | 20 个不同 PDF 串行处理，检查 20 个独立哈希和导出回执 |
| 人工暂停 | 本地验证码页面阻塞当前篇，后续篇/任务不越过；侧栏暂停、继续、跳过 |
| 重复提交 | 相同 key 返回同一任务；同 key 改请求或同 listId 改清单拒绝 |
| 错误论文 | 错 DOI 与错题名文件进入 mismatch，Agent 正文/导出与用户强行批准均被阻止 |
| 断线恢复 | 批量下载期间停止并重启真实本机服务，保留配对/SQLite/文件后完成任务；单测另验证旧租约拒绝和过期人工恢复 |
| 文件冲突 | 预置同名不同内容文件，导出返回冲突，原内容保持；同内容可重用 |

其他检查包括保存弹窗后的文件回传、blob 下载、直接 PDF、预览确认、重新获取、已保存/已导出的不同显示、清单 JSON 可见、官网链接属性、320/420/600 像素侧栏、无未处理 worker Promise 异常、关闭侧栏时的原生通知 API 成功。

浏览器测试中修复了一处旧逻辑竞态：正在收尾时收到“继续/监听”的唤醒可能丢失。公开版记录待唤醒标记，收尾后立即再检查队首，避免依赖下一次 30 秒轮询。

Python 测试有一条上游 Starlette 关于 httpx TestClient 的弃用提示；不影响本轮结果。没有据此宣称项目不存在任何生产漏洞或已通过独立安全审计。

## 复现

在源码根目录安装测试依赖后执行 README 中的 pytest、Node 和 browser_smoke 命令。浏览器脚本默认使用 Playwright Chromium；若使用已安装的测试 Chromium，将 `LITSCOUT_SMOKE_CHROMIUM` 设为其可执行文件绝对路径。不要设成日常 Profile 启动脚本。

浏览器服务端口为 57139，数据、下载目录、Profile 和 TLS 证书使用本次临时目录，完成后清理。环境变量变更只在测试进程，不写系统配置。可设置 `LITSCOUT_SMOKE_SCREENSHOT` 保存侧栏截图，设置 `LITSCOUT_SMOKE_REPORT` 保存 JSON 检查结果。不要公开含用户数据或个人路径的截图/日志。
